# 本地试用与分发

当前版本：0.2.0 原生 macOS 本地预览。仓库提供源代码和本地构建脚本，应用使用 ad-hoc 开发签名。Developer ID 发行签名、Apple 公证及独立下载环境验证尚未完成；源码仓库的可见性不改变这些应用发行条件。

## 环境与构建

- 最低构建目标为 macOS 14，需要 Swift 5.9+ 工具链；无第三方运行依赖。
- 开发阶段实际使用过 macOS 15.1、Swift 6.0.2、Apple Silicon。其他系统和架构需另外验证，最低目标不等于实机覆盖。
- 当前打包脚本仅接受 arm64 应用，不生成 Intel 或 Universal 包。
- 应用版本从仓库根目录的 `VERSION` 读取。构建输出为 `dist/DevFlow.app`，构建和模块缓存留在仓库的 `.build` 中。

在仓库根目录执行：

```sh
bash scripts/test.sh
bash scripts/build-app.sh
open dist/DevFlow.app
```

`test.sh` 执行真实 Swift 断言并返回检查结果；`build-app.sh` 构建应用、写入资源并核验 ad-hoc 签名。检查输出必须对应当前源码。核心检查通过不代替原生交互、安装环境或业务验收，历史检查数量不作为当前版本通过证明。

## 本地试用流程

1. 点击“查看复盘样本”。首页提示为“先看看教学复盘样本”；样本明确标为合成教学记录，用于浏览关联、失败与限制，不代表真实项目状态或执行证据。
2. 点击“导入项目资料”，选择 Markdown 资料目录、单文件或 DevFlow JSON。schemaVersion=2 包提供需求、任务、测试、执行、问题与交付工作台；schemaVersion=1 继续支持。
3. 通过搜索、类型、日期和关联定位记录；查看来源摘录，必要时关联原始资料目录。缺失来源、摘要不匹配和未知时间保留提示。
4. 可单独接入一个 Codex JSONL，或为当前项目手动关联最多 8 个会话。只读取明确选择且格式支持的公开动作。
5. 编辑、保存和复制反馈，再由用户决定是否粘贴回开发聊天。复制不会发送消息或改变问题是否已解决的事实。
6. 手动刷新，或让前台当前项目每 15 秒读取。可暂停自动资料刷新或停用单个会话；读取失败保留已有内容，暂停不会停止代理。

工作区默认保存在 `~/Library/Application Support/DevFlow/workspace.json`，前一版备份为同目录下的 `workspace.json.backup`。可通过 `--workspace` 参数指定自选工作区文件，例如在仓库根目录隔离试用：

```sh
mkdir -p .build/local-preview
open dist/DevFlow.app --args --workspace "$PWD/.build/local-preview/workspace.json"
```

应用不会执行导入资料中的命令或修改来源项目。工作区、导出和剪贴板的保留边界见 [隐私说明](PRIVACY.md)。

## 证据 CLI

`DevFlowEvidence` 是源码中的 macOS 辅助工具，当前预览 ZIP 不包含它。使用 [代理接入指南](agent-quickstart.md#获取实际可用的证据工具) 的构建步骤取得实际路径。

`contracts` 输出每个测试设计的合同摘要，供实际执行前冻结；`inspect` 只读评估指定包及可访问的本地证据。退出 0 表示报告生成成功，应继续检查 `state`、`validPass`、`warnings` 和 `validationErrors`。它不会执行测试，也不会包含 App 中另外手选关联的全部会话。

## 打包本地预览

在应用构建完成后执行：

```sh
LC_ALL=C bash scripts/package-preview.sh
```

脚本读取应用实际版本，生成 `dist/DevFlow-<版本>-preview-macOS-arm64.zip`、同名 `.sha256` 和解压目录。包包含应用、试用说明、隐私说明和更新记录，不打包用户工作区、来源项目、原始会话、开发证据目录或旧应用备份。已有同名输出时拒绝覆盖，可使用 `--name` 或 `--output-dir` 选择新输出；选项见脚本 `--help`。

打包脚本只核验现有 ad-hoc 签名，不重新构建、不上传、不调用发行签名身份，也不提交公证。传输后 macOS 可能对未公证应用施加限制；本地签名完整性检查不能代替正式发行验证。

每次交付应保存当前源码版本、真实检查输出、构建结果、应用版本、最终 ZIP 摘要及签名结果。原生检查应覆盖导入、来源查看、历史筛选、反馈保存/复制、刷新失败、重启持久化和解压迁移；未执行的场景应明确留下。

## 正式分发前仍需完成

- 使用合适的 Developer ID 身份签名，并保存针对最终应用的核验结果。
- 完成 Apple 公证、票据及系统评估，确保结果对应实际分发产物。
- 在独立下载和安装环境验证首次启动、资料权限、主要流程及卸载边界。
- 明确支持的系统和架构，说明升级与数据兼容策略；当前没有自动升级。
- 冻结最终版本和摘要，复核随包样例、截图、摘录、品牌资源及依赖的公开范围。

源码托管或许可证不授权上传用户导入资料，也不构成上述事项已经完成。更多范围见 [产品](PRODUCT.md)、[路线与验收](ROADMAP.md)、[贡献指南](../CONTRIBUTING.md) 和 [许可证](../LICENSE)。
