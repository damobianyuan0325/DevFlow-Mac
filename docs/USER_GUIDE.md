# DevFlow 用户指南

适用于 `v0.2.0-preview.3`（App 版本 `0.2.0`）。这是原生 macOS 预览版，当前下载包面向 Apple Silicon，最低构建目标 macOS 14。其他系统组合需要实际验证；不提供 Intel 或 Universal 下载包。

DevFlow 在本机只读查看你选择的资料，不调用外部模型、不自动执行导入内容，也不向开发代理发送消息。先用合成教学样本熟悉界面，再导入自己的项目。

## 下载与安装

1. 打开 [v0.2.0-preview.3 固定 Release 页](https://github.com/damobianyuan0325/DevFlow-Mac/releases/tag/v0.2.0-preview.3)。仓库已开源，浏览源码和下载本版无需登录或申请访问权限；若页面无法访问，核对链接和网络。
2. 在 Assets 中下载 `DevFlow-0.2.0-preview.3-macOS-arm64.dmg`。它是应用包，不是 GitHub 自动提供的 Source code 源码归档。运行已构建的应用本身不需要 Swift 工具链。
3. 一并下载 `SHA256SUMS.txt`，按 [发布指南](RELEASE.md#检查下载文件) 核对文件。若只下载应用包，核对清单中对应这一行即可；App内已包含双技能；独立技能ZIP是可选下载。
4. 双击 DMG 打开安装卷，将其中的 `DevFlow.app` 复制到 Finder 的“应用程序”（Applications）目录。如果要替换旧版，先退出应用并按下文备份工作区。
5. 弹出安装卷，从“应用程序”打开 DevFlow。在应用菜单“关于 DevFlow”核对预览版本 `0.2.0-preview.3`；首次可选择首页“先看看教学复盘样本”，无需导入私人资料即可开始浏览。

当前应用只有 ad-hoc 本地签名，**没有 Developer ID 发行签名或 Apple 公证**，安装和使用本预览版不要求购买 Apple 开发者会员。下载后首次启动可能被 macOS 限制。

若提示“无法验证开发者”或“Apple 无法检查是否包含恶意软件”，并且你已确认下载来源和摘要，可以按 Apple 提供的单个应用放行流程操作：先尝试打开 App，再进入 **系统设置 → 隐私与安全性 → 安全性 → 仍要打开**，核对应用名称并确认。仅对这个应用设置例外，不关闭全局 Gatekeeper。按钮可能受系统版本或设备管理策略限制；见 [Apple 官方说明](https://support.apple.com/en-us/102445)。

若提示会损害电脑、检测到恶意软件、文件损坏，或摘要不一致，不按上述步骤强行放行；保留提示并核对下载。无法放行时可选择 [从源码构建](RELEASE.md#从源码构建)。本机安装检查不能保证每台独立 Mac 的首次启动行为。

## 先看教学复盘样本

没有项目时点击“先看看教学复盘样本”；已有项目时可以从侧栏底部“打开复盘样本”重新载入。样本是合成教学记录，演示需求、研发、检查、失败、修复、决策和交付的关联，不代表真实项目或真实执行已经发生。

选择一条记录，阅读标题、来源类别、事件时间、原文摘录、关联记录和限制。按类型切换，或在“搜索标题、内容或来源”中查找关键词。启用“历史截止日期”后按已知事件日期回看；未知日期另列，不会用导入时间填充。

样本是固定内容，不能用它观察实际项目更新。普通历史样本没有监督计划时，不会出现完整的需求验收工作台。

## 导入自己的资料

首页选择“导入项目资料”；已有项目时使用工具栏“导入项目”，或菜单“导入项目资料…”（⌘O）。可选内容包括 Markdown 资料文件夹、单个 Markdown 文件、DevFlow JSON 包，以及明确选择的单个 Codex JSONL 会话。

导入是只读操作。DevFlow 不运行文件中的命令，不启动项目服务，不修改被导入的仓库。Markdown 提取受文档结构、文件数量和大小限制；遇到未识别、截断或无法读取的内容会显示限制，不能把结果当作全部研发历史。

JSON 中的来源路径相对资料根解析。包移动过、原文件不在旁边或需要重绑目录时，选中项目，点击工具栏“关联原始资料”，再选择真实资料根。“打开原文件”和“在 Finder 中显示”只用于可访问的普通来源；缺失或摘要已变时按提示核对，不用新内容冒充旧来源。

## 查看 schemaVersion=2 监督包

由开发代理按 [接入指南](agent-quickstart.md) 生成项目的 `devflow-supervision.json`，再按普通 JSON 导入。在“监督工作台”中可切换：

| 栏目 | 主要用途 |
| --- | --- |
| 项目总览 | 查看原话、阶段简报、待介入事项和覆盖边界 |
| 需求与任务 | 查看需求拆解、假设、验收条件和任务对应 |
| 测试与验收 | 分开查看“测试用例 · T”“执行证据 · E”“需求验收 · A” |
| 问题与交付 | 核对问题、真实修复、有效复验及交付文件引用 |
| 需要我介入 | 查看具体缺口，生成或继续编辑反馈 |
| 来源 | 查看本项目的来源、覆盖及读取情况 |

“回查动作与历史”回到记录列表。存在一个用例不表示它已经执行，工具返回不表示测试通过，修复声明也不表示问题已经有效关闭。过期、缺证、失败和部分覆盖是不同状态；保留的旧失败不必然是当前尚未解决的问题。

客户端只核对声明的本地证据。来源摘要相同不证明业务预期充分、日志绝对真实或检查覆盖完整。没有合同、日志、计数或时间时，应让开发代理补充真实来源或执行新的检查，不能手填虚构结果来变绿。

## 关联开发会话

“接入开发会话”用于把手选的一个 Codex JSONL 作为独立项目导入。如果已有项目或监督包，选中它，点击“关联开发会话到此项目”，把相关会话归入同一个项目；每个项目最多关联 8 个会话，教学样本不能关联实际会话。

DevFlow 不扫描其他聊天。它提取当前格式支持的公开需求、进展、工具调用及结果、命令和文件变更，排除内部推理、系统配置及二进制载荷。只提供父会话里的子代理报告，不能展示其完整内部过程；批量脚本未独立记录的步骤也无法还原。

在项目侧栏的上下文菜单选择“管理项目来源”，可查看主来源及已关联会话。关闭某个会话的“读取此会话”开关会停用后续读取，但仍保留此前导入的内容。原始会话可能包含私人配置，因此会话记录不提供直接打开原 JSONL 的按钮，阅读的是过滤后的摘录。

## 手动反馈

普通记录的详情中有“整理反馈”；监督对象旁也有“整理反馈”按钮。先阅读来源和限制，再编辑希望核查的问题、预期及补充说明。点击“保存草稿”保留本地编辑，点击“复制反馈”后自行粘贴回开发聊天。

监督反馈弹窗还可“保存并关闭”。保存和复制不会发送消息、暂停代理、修改源码或改变问题状态。下一轮由开发代理核对当前事实、处理已授权问题并回写，用户再刷新资料；可把 [devflow-resolve](../skills/devflow-resolve/SKILL.md) 的完整目录交给该代理使用。

## 刷新与暂停

工具栏“刷新记录”（菜单“刷新当前项目”，⌘R）立即重读当前项目。“管理项目来源”中也有“立即读取资料”。当前项目选中、应用位于前台且未暂停时，每 15 秒自动读取；应用退出或后台状态不保证持续采集。固定教学样本不自动刷新。

点击“暂停资料刷新”只停止自动读取，手动读取仍可用；“恢复资料刷新”重新启用它。单会话开关只影响该来源。读取失败会保留上次成功内容并显示错误；没有新记录不能证明代理仍在工作、已经停止或卡住。

## 备份、导出与升级

默认工作区是：

```text
~/Library/Application Support/DevFlow/workspace.json
```

同目录 `workspace.json.backup` 保存前一版内容。它不是无限历史备份，后续保存可能更新这份备份。工作区包含项目绑定、记录摘录、历史、监督计划和反馈草稿，应用没有额外加密。

升级前：

1. 退出 DevFlow。在 Finder 的“前往文件夹”中打开 `~/Library/Application Support/DevFlow/`，把整个目录复制到自己选择的备份位置；若使用自定义 `--workspace`，备份实际指定的位置。
2. 保留仍需回查的原资料目录和会话文件。工作区备份中的引用不会自动打包这些外部原件。
3. 下载指定新版本并核对摘要，替换“应用程序”中的 App，再启动并核查项目、草稿及来源状态。没有自动升级功能，也不承诺任意新旧版本双向兼容。
4. 若需回退，先退出应用并保留当前工作区副本，再恢复升级前的应用及匹配的工作区备份。不要用旧 App 覆盖唯一的新工作区。

工具栏“导出记录”（菜单“导出当前记录…”）导出记录与摘录，含监督计划时也导出计划和证据引用；当前不包含反馈草稿或本机会话绑定设置，因此导出不能替代完整工作区备份。导出、备份和剪贴板可能含敏感资料，分享前按 [隐私说明](PRIVACY.md) 检查。

## 移除与卸载

在项目侧栏的上下文菜单选择“从工作台移除”，会移除工作区中的该项目与草稿，不删除原始项目或会话。前一版备份、已导出的文件及剪贴板可能仍保留内容。

卸载应用时先退出，再把“应用程序”中的 DevFlow.app 移入废纸篓。若还要清除应用数据，先确认需要的备份，再自行处理上述工作区目录、自定义工作区及导出文件；保留或删除源项目由用户另行决定。删除 App 本身不会一并删除这些资料。

## 常见问题

| 现象 | 核对方式 |
| --- | --- |
| Release 页 404 或看不到 Assets | 核对版本链接、网络及 Release 状态；公开下载无需申请仓库权限，不要向他人提供账号密码 |
| 下载后 macOS 不允许启动 | 本版尚未正式签名和公证；确认来源及摘要后按上方单应用“仍要打开”步骤处理；不关闭全局系统保护 |
| 没有“监督工作台” | 当前可能是普通 Markdown、schemaVersion=1 或单会话项目；要有符合协议的 schemaVersion=2 监督计划 |
| 来源找不到或摘要不符 | 确认文件是否移动或修改，用“关联原始资料”重绑正确目录；旧执行身份不能改写成新文件身份 |
| 看到旧失败，但最新检查已通过 | 历史失败会保留；查看对应要求的当前适用性及最新有效复验，不按红色记录条数判断项目状态 |
| 看不到某些动作或工具结果 | 检查是否接入正确会话、格式是否受支持、是否存在截断或未记录步骤；缺失不等于失败 |
| 新记录没有出现 | 选中正确项目，确认前台、未暂停及会话开关；先手动刷新并读取具体错误 |
| 工作区读取失败 | 应用会保护原文件；先退出并备份，再检查真实错误和可用备份，不直接删除唯一工作区 |
| 需要让 AI 处理反馈 | 把已编辑反馈和完整 devflow-resolve 技能交给原开发代理，明确项目及授权范围；App 不自动发送 |

## 给 AI 代理接入

应用 DMG 中的 App 已内置完整 `skills/`；也可单独下载 `DevFlow-agent-skills-0.2.0-preview.3.zip`，或使用同 tag 源码中的 `skills/`。必须保留每个技能目录内的相对文件，不能只复制 SKILL.md；按宿主规则选择技能，或让代理直接阅读完整说明。

- [devflow-record 与接入指南](agent-quickstart.md)：从一句话需求留下拆解、任务、真实动作和测试证据。
- [devflow-resolve 与问题处理指南](agent-resolution.md)：核对反馈，补证或修复，复验并回写。

两技能可独立使用，`gated-delivery` 为显式选择的可选适配。需要证据 CLI 的代理可使用 App 内置的 `DevFlowEvidence`，或按接入指南自行构建；独立技能 ZIP 不含 CLI。客户端不会自动安装或调度这些技能。

## 安装后把技能交给 AI

技能和CLI都在App内部，随拖拽一起安装。DevFlow菜单可“打开技能与接入说明…”或“复制给 AI 的接入说明”。完整步骤见[安装后接入](../AGENT_INSTALL.md)。升级前保留旧App；内置技能不可原地修改，需调整时复制到项目或宿主配置位置，检查同名旧技能后再更新。
