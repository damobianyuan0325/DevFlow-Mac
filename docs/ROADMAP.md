# 路线与验收边界

当前基线为 0.2.0 本地预览。下表说明已有功能及后续变更必须保持的可观察条件；它不是对任意本地构建的自动通过声明。验证应针对当前源码、实际环境和产物保存真实结果。

## 当前功能与回归入口

| 范围 | 必须保持的行为 | 检查入口 |
| --- | --- | --- |
| 导入与来源 | 有效 JSON/Markdown 可读；坏输入、不安全路径及超预算明确拒绝或提示；不改原项目 | `ImporterTests`、`SupervisionTests`，加真实原生导入 |
| 项目与历史 | 搜索、类型、日期、关联、来源查看可用；未知日期和旧失败保留 | `WorkspaceTests`，加原生筛选与来源查看 |
| 反馈与持久化 | 草稿可编辑、保存、复制、关闭重开读回；坏工作区不被空数据覆盖 | `WorkspaceTests`、监督反馈检查，加原生重启 |
| 持续读取 | 新资料刷新可见；失败保留最后内容；暂停和单会话停用只影响资料读取 | `ProjectSourcesTests`，加受控增量和原生读取 |
| 公开会话动作 | 手选 JSONL，调用与返回独立，按来源关联与去重；排除内部推理和配置，披露缺口 | `SessionImporterTests`，加手选会话导入 |
| 监督关系 | R/A/U/T/E、问题和产物引用有效；原话、拆解和先前计划快照可查 | `SupervisionTests`、协议及 CLI 读回 |
| 当前适用性 | 合同、源码、日志、版本、计数与层级匹配；缺证、过期、失败各自显示 | `SupervisionTests`，含合同变化及无效通过反例 |
| 问题闭环 | 原失败保留；真实修复及严格在其后、当前仍有效的复验共同支持关闭 | `SupervisionTests`，加界面问题查看 |
| 原生应用与打包 | 当前 `.app` 能运行，资源和版本正确；预览 ZIP 内容、摘要和 ad-hoc 签名可核对 | `scripts/build-app.sh`、原生操作、`scripts/package-preview.sh` |
| 可移交接入 | 两技能完整可读，教学例子明确隔离；反馈处理可独立使用，适配只在显式选择后生效 | `Tests/AgentSkills`，加独立示例执行和真实 CLI 读回 |

Swift 检查统一通过 `bash scripts/test.sh` 运行。核心检查、技能脚本、CLI 读回、原生 UI 与解压后的应用验证应分别报告。旧版本通过、编译成功、检查条数或一次导出不能代替当前完整验收。

固定反例：新失败不能被旧成功覆盖；缺少日志或计数不能变成通过；复制反馈不能标成已发送；不把用户未选择的会话自动纳入；不把合成教学样本当成真实项目证据；没有新任务时仍可回查历史。

## 当前未完成的发行工作

- Developer ID 发行签名、Apple 公证及对应产物的系统评估。
- 独立下载和安装环境中的首次启动、权限、主要流程及迁移验证。
- macOS 14、其他系统版本以及 Intel/Universal 的明确兼容性验证；当前预览打包仅接受 arm64。
- 自动升级及正式升级/数据兼容策略。

这些工作不由本地 ad-hoc 签名、源代码托管或核心检查通过自动完成。具体条件见 [试用与分发](RELEASE.md)。

## 尚未实现的能力

完整跨代理、跨工具动作采集，客户端内置 AI 需求拆解或语义质量判断，自动调度技能、控制代理、发送反馈、账户、云同步和外部模型接入均不属于当前能力。费用与用量没有可靠来源时继续显示未接入。这些是范围说明，不是已排期的发布承诺。

后续工作按明确用户目标形成有限任务，先固定原话、预期、范围、检查入口和停止条件，再连续实现、核对及交付。新增检查应针对实际缺口；重复发现相关缺陷时说明程序根因与前次漏检原因，并补最小有效守护。历史失败和未验证项继续保留。
